## 1. Мета роботи

Навчитися працювати з рядками, реалізовувати алгоритми обробки тексту, порівнювати наївні та оптимізовані алгоритми, досліджувати жадібні алгоритми та обґрунтовувати вибір рішення за допомогою вимірювань.

## 4. Завдання 1. Пастки рядків

Досліджено три випадки:

1. Конкатенація рядків через += та StringBuilder.
2. ToLower() та OrdinalIgnoreCase.
3. Ординальне та культурне сортування слів із літерою ґ.

### Результати вимірювань

Заповнити після запуску програми:

| Операція | Перший варіант, мс | Другий варіант, мс |
|---|---:|---:|
| 10 000 додавань | | |
| 100 000 додавань | | |
| Порівняння слів | | |

Висновок:

StringBuilder дозволяє зменшити кількість проміжних рядків. OrdinalIgnoreCase дозволяє порівнювати рядки без створення копій через ToLower(). Культурне та ординальне сортування можуть давати різний порядок.

## 5. Завдання 2. Нормалізація тексту

Реалізовано два алгоритми:

- Наївний: Trim, Replace, Substring.
- Оптимізований: один прохід із StringBuilder.

### Результати

| Символів | Наївно, мс | Швидко, мс | Різниця |
|---:|---:|---:|---:|
| 1 000 | | | |
| 10 000 | | | |
| 50 000 | | | |

Обидва алгоритми повинні повертати однаковий результат.

Висновок:

Швидкий алгоритм виконує нормалізацію за один прохід, не створюючи багато проміжних рядків. Перевагу конкретної реалізації визначено за фактичними замірами.

## 6. Завдання 3. Пошук підрядка

Реалізовано власний алгоритм NaiveIndexOf із лічильником порівнянь.

Параметри:
- Текст повторів: 10 000 символів П.
- Шаблон: 1 099 символів П та один символ Р.
- Довжина шаблону: 1 100 символів.

### Результати

| Вхід | Порівняння | Власний час, мс | IndexOf, мс |
|---|---:|---:|---:|
| Проза, наявне слово | | | |
| Проза, відсутній шаблон | | | |
| Повтори, персональний шаблон | | | |

Пояснення:

У третьому тесті майже всі символи шаблону збігаються з текстом. Останній символ не збігається, тому алгоритм повторює довге порівняння для багатьох позицій.

Вбудований IndexOf використовує оптимізовану реалізацію .NET і має менші накладні витрати.

## 7. Завдання 4. Жадібний алгоритм

Моя задача — вибрати найбільшу кількість заявок без перетинів.

Жадібне правило: вибирати заявку, яка закінчується раніше.

Еталон: повний перебір можливих комбінацій.

Виконано 100 випадкових тестів через Random(17).

### Результати

| Показник | Значення |
|---|---:|
| Успішних тестів | |
| Найгірше відставання | |
| Перебір на 15 заявках, мс | |
| Перебір на 20 заявках, мс | |

### Контрприклад 1. Найраніший початок

Заявки:
- [0; 10]
- [1; 2]
- [2; 3]

Вибір за найранішим початком дає одну заявку. Оптимальне рішення — дві заявки [1; 2] та [2; 3].

### Контрприклад 2. Найкоротша заявка

Заявки:
- [0; 3]
- [3; 6]
- [2; 4]

Вибір найкоротшої заявки [2; 4] дає лише одну заявку. Оптимум — [0; 3] та [3; 6].

Висновок:

Сортування за часом завершення є оптимальним для задачі вибору максимальної кількості неперетинних заявок.

## 8. Завдання 5. Вибір алгоритму

1. Розмір вхідних даних становить 50 000 символів. Це український прозовий текст.
2. Потрібно виконати нормалізацію всього тексту. Це один запит на один вхідний текст.
3. Якщо текст змінюється, нормалізацію необхідно повторити.
4. Важливі час виконання та використання пам'яті. Наївний алгоритм простіший, швидкий виконує обробку за один прохід.
5. У стандартній бібліотеці є StringBuilder, Trim, Replace та char.IsWhiteSpace.
6. Остаточний вибір зроблено на основі вимірювань для 1 000, 10 000 та 50 000 символів.
